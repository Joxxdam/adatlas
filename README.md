# DAYWIZ AdAtlas

DAYWIZ AdAtlas는 상품 상세페이지의 공개 근거와 사용자 제공 광고 레퍼런스를 결합해 바로 검수할 수 있는 광고 이미지를 만드는 Next.js 기반 광고 콘텐츠 운영 도구입니다.

기본 제작 경로는 새 장면을 처음부터 만들지 않습니다. `이미지참고복사용.zip`에서 상품군·상품 형태·구도가 호환되는 완성 광고 6장을 중복 없이 무작위로 선택하고, 원본 구조를 무손실 복사한 뒤 URL 상품과 ProductTruth 문구만 단계별로 교체합니다.

## 왜 만들었는가

빈 화면에서 매번 새 디자인을 생성하면 광고 완성도와 상품 동일성이 흔들리기 쉽습니다. AdAtlas는 사용자가 선별한 완성 광고의 시각 구조를 출발점으로 삼고, 공개 상품 근거와 연결 데이터를 실제 상품·문구·소재코드·광고명·UTM까지 한 흐름으로 연결합니다.

핵심 사용자는 광고할 상품을 찾는 퍼포먼스 마케터, 상품 근거를 광고 기획으로 바꾸는 콘텐츠 마케터, 그리고 승인 가능한 완성 소재를 빠르게 검토해야 하는 광고주·디자이너입니다.

## 기본 제작 흐름

```text
상품 상세페이지 URL 분석
→ ProductTruth 사실만 구성하고 광고용 상품명·프로모션 토큰 분리
→ 상품군·상품 형태·구도 호환 점수를 통과한 ZIP 풀에서 중복 없이 광고 6장 무작위 선택
→ 선택 결과를 GenerationJob에 저장해 재시도·복구에도 고정
→ 업로드 또는 운영자의 명시적 재분석 때 저장한 실제 OCR 원문·줄바꿈·문장부호를 로드
→ 여섯 원문의 말투와 구조를 유지하고 상품 관련 사실만 ProductTruth 값으로 교체
→ 비생성 문구 검증, 실패 항목만 배치로 최대 1회 수정
→ 레퍼런스 광고 원본을 작업 마스터로 바이트 동일 복사
→ URL 상세페이지 원본을 기준으로 상품만 교체
→ ProductTruth 문구·가격·혜택만 교체
→ 레퍼런스·상품 원본·정확 문구를 비교하는 비생성 QA, 치명 오류에만 AI 수정 최대 1회
→ 1200×1200 JPEG, 800KB 이하 검증
→ 소재코드·권장 광고명·UTM·랜딩 URL과 함께 전달
```

서비스의 기본 사용자 흐름은 다음 네 단계입니다.

1. 광고 후보 찾기
2. 상품 선택 또는 URL 입력
3. AI 광고 6장 만들기
4. 결과 확인 및 테스트

## 별도 기능: 카테고리 후보와 대표 이미지

`카테고리 광고 후보 분석 → 카테고리 대표 이미지 제작`은 상품 URL을 기준으로 광고 6장을 만드는 기존 기능을 수정하거나 대체하지 않는 독립 기능입니다.

```text
읽기 전용 BigQuery 상품 집계
→ 상품명 기반 별도 카테고리 정규화(원본 상품명 보존)
→ 최근 7일/직전 7일 및 최근 4주 흐름 분석
→ 카테고리 한 개 선택
→ 같은 광고주·카테고리의 실제 상품 이미지 3~5장 선택
→ 하나의 에디토리얼 콘셉트 구성
→ 1200×1200 정사각형과 1080×1920 세로형을 각각 재배치
→ 서버 한국어 문구 렌더링
→ 두 규격 ZIP 및 카테고리 아카이브 저장
```

- 메뉴는 `광고 후보 찾기 > 카테고리 후보`와 `03 카테고리 이미지`로 분리되어 있습니다.
- 카테고리 후보를 거치지 않고 `/category-images`에서 광고주와 카테고리를 직접 선택할 수 있습니다.
- 상품 광고의 GenerationJob, H01~H06, ProductTruth 가격 후킹, 상품 광고 레퍼런스 6장 경로를 호출하지 않습니다.
- 서로 다른 광고주 또는 카테고리의 원본 이미지를 한 결과에 섞지 않습니다.
- 근거가 부족한 동급 업체 비교는 수치를 추정하지 않고 `비교 데이터 부족`으로 표시합니다.
- 패션 참고 이미지 9장은 구도·시즌 무드·큰 문구 위계만 참고하며 원본 업체명, 워터마크, 문구, SNS UI, 인물·의상 픽셀을 결과에 복사하지 않습니다.
- 결과 문구 수정은 저장된 비문자 베이스를 유지하고 텍스트 레이어만 다시 렌더링합니다.
- 카테고리 결과는 `/archive?kind=category`에서 상품 광고와 구분해 확인합니다.

홈 화면은 두 가지 제작 시작 방식과 실제 제작 레퍼런스 바로가기만 간결하게 제공합니다. 사이드바의 `성과 확인`과 `이미지 제작 관리 도구`는 `이미지 콘텐츠 > 광고 제작` 아래의 독립 드롭다운으로 배치합니다. 이미지 제작 관리 도구에는 별도 톱니바퀴 아이콘을 표시하지 않으며, 홈의 레퍼런스 카드는 실제 제작에 사용하는 `/admin/references?tab=library`로 바로 연결합니다.

제작 화면에서는 `이 상품으로 광고 만들기`를 한 번 누르면 별도 설정 없이 서버 작업이 시작됩니다. 기본 화면은 `현재 n장째 제작 중`, 완료 `x/6`, 1~6 상태칸만 보여주고 완성된 광고를 한 장씩 즉시 추가합니다. 대기 중인 레퍼런스와 내부 교체·검수 정보는 기본 화면에 펼치지 않습니다.

이미지가 생성되면 AI 완성도 판정과 관계없이 즉시 화면에 표시되고 개별 다운로드할 수 있습니다. 6장의 최종 JPEG가 모두 준비되면 `6장 ZIP 다운로드`가 활성화되며, ZIP을 받으면 이번 제작 흐름은 끝납니다. 같은 상품 URL을 다시 입력해 분석하면 이전 완료 작업을 복원하지 않고 새 광고 6장 제작을 시작합니다. 개별 수정, 문구 편집, 선호 저장과 제작 정보는 완성 카드 또는 고급 도구를 펼쳤을 때만 표시합니다.

이미지 제작과 동시에 같은 상품 6장에 공통으로 사용할 상품 광고 설명 문구를 상품당 한 번만 생성합니다. 설명 문구·광고명·UTM은 이미지 완료를 기다리지 않고 결과 화면에서 먼저 확인할 수 있으며 TXT·JSON·CSV 및 전체 ZIP으로 내려받을 수 있습니다.

## 이미지 아카이브 관리

`/archive`에서는 광고주·상품별로 생성 이미지를 확인하고 개별 삭제하거나 여러 장을 선택해 한 번에 삭제할 수 있습니다. 각 상품 묶음의 `이 상품 전체 선택`과 화면 전체의 `현재 목록 전체 선택`을 지원하며, 삭제 전에는 선택 장수와 확인 창을 표시합니다. 아카이브 삭제는 목록에서 항목을 제거하는 작업이며 원본 생성 작업과 이미지 파일은 보존합니다. 삭제 기록은 별도로 저장되므로 새로고침해도 같은 항목이 다시 나타나지 않습니다.

## 레퍼런스 선택과 문구 기획

실제 사용 장수와 분류는 항상 `data/native-creative-reference-library.json` 및 관리 화면의 현재 값을 기준으로 증감합니다.

`/admin/references`의 `제작 레퍼런스` 탭이 이 풀의 관리 화면입니다. 이미지를 올리면 로컬 Codex가 광고 속 상품을 기준으로 `패션 / 식품 / 화장품` 중 하나로 자동 분류하고 실제 광고 문구도 원문 그대로 한 번 추출합니다. 운영자는 OCR 오류를 수정하거나 문구 적응 사용 여부를 끌 수 있고, 재분석은 버튼으로 명시적으로 실행합니다. 생성 작업 도중에는 OCR을 다시 실행하지 않습니다. 삭제한 이미지는 새 수동·자동 제작의 무작위 선택 대상에서 즉시 제외됩니다.

- 레퍼런스 구분은 `패션 / 식품 / 화장품` 세 그룹만 사용합니다.
- `과일/농산물`은 별도 대카테고리가 아니라 식품 카드에서 운영자가 직접 켜고 끄는 하위 선택 태그입니다.
- 과일·채소·농산물 상품은 `식품 > 과일/농산물`로 지정한 레퍼런스만 사용하며, 6장 미만이어도 일반 식품 레퍼런스로 보충하지 않습니다.
- 고기와 일반 식품은 과일/농산물 태그 항목까지 포함한 식품 전체 풀에서 호환 레퍼런스를 선택합니다.
- 건강·웰니스, 퍼스널케어, 생활·기능성 제품은 화장품 그룹에 함께 포함합니다.
- 문구 원문이 준비된 호환 레퍼런스를 우선 선택하고, 마이그레이션 중인 기존 항목은 제작 중단을 막는 범위에서만 보조 후보로 사용합니다.
- 상품 형태·구도·슬롯 호환 점수를 통과한 후보가 6장보다 적으면 다른 그룹으로 보충하지 않고 부족 상태를 표시합니다.
- 신규 기본 작업은 레퍼런스를 고르기 전에 HookPlan·후킹 후보·범용 카피 초안을 만들지 않습니다.
- H01~H06은 저장 호환을 위한 내부 순번일 뿐 후킹 전략이나 레퍼런스 선택 기준이 아닙니다. 화면에는 `소재 01~06`으로 표시합니다.
- 가격·혜택·후기·효능·인증은 ProductTruth에 근거가 있을 때만 최종 문구에 사용합니다.
- 새 작업에 배정된 6장은 재시도·문구 수정·새로고침·서버 복구에서도 다시 추첨하지 않습니다. `호환 레퍼런스도 새로 뽑아 6장 전체 새로 만들기`에서만 다시 추첨합니다.

`CategoryCreativeProfile`과 `CreativeBrief`는 상품 사실·카피·QA 보조 정보로 남지만 레퍼런스 디자인을 새 장면으로 재해석하는 지시로 사용하지 않습니다.

## AI 엔진 정책

기본 엔진은 설치된 Codex CLI와 현재 ChatGPT 로그인을 사용하는 `codex_local`입니다.

- 레퍼런스 원문 OCR: 업로드 또는 운영자의 명시적 재분석에서만 실행하고 manifest에 저장
- 문구 계획: 여섯 레퍼런스를 한 번의 짧은 배치로 처리하고 실패 항목만 최대 1회 배치 수정
- 광고 편집: 레퍼런스 무손실 복사·상품 교체·문구 교체·치명 QA 수정을 분리하며 구조 복사 단계는 생성 호출 없음
- 결과별 세션: H01~H06이 각자 짧은 세션 하나를 열고, 상품 교체·문구 교체·개별 QA·치명 오류 보정·재검수를 같은 세션에서 수행
- 기본 동시성: 상품당 결과 3장, 전체 로컬 Codex 실행도 최대 3개, 실제 품질 오류에만 자동 QA 수정 최대 1회
- 로컬 Codex가 불가능할 때는 검증된 ProductTruth 사실만 사용한 최소 문구로 안전하게 계속하며, 과거 후킹 엔진으로 fallback하지 않음
- 유료 OpenAI API는 UI에서 `openai_api`를 명시 선택하고 서버 플래그를 켠 경우에만 사용
- 로컬 Codex 실패를 유료 API로 자동 전환하지 않음

## 상품 이미지 원칙

- 상세페이지의 실제 상품 사진을 우선 사용합니다.
- 패키지 형태, 라벨 인상, 색상, 옵션과 수량을 최대한 보존합니다.
- 자동 누끼와 기존 광고 배너는 기본 참조에서 제외합니다.
- 정면, 라벨, 실제 판매 구성, 손·사용 장면, 질감·원료 순으로 중복 없는 원본을 최대 5장 전달합니다.
- 확인되지 않은 가격, 할인, 구성, 후기, 평점, 효능, 인증, 원산지와 성과 수치를 생성하지 않습니다.
- 상품과 무관한 이미지를 fallback으로 사용하지 않습니다.
- 상품 교체 단계에서는 상품 외 픽셀을 잠그고, 문구 교체 단계에서는 상품과 배경·레이아웃을 잠급니다.
- 육류는 상세페이지 원본의 부위·마블링·지방 비율·색·두께·판매 구성을 사실 기준으로 삼고, 장면의 원근·결·수분·접촉광과 자연스럽게 이어지도록 생성합니다. 다른 부위나 등급을 만들거나 원본 사진 사각형/누끼가 붙은 모습은 허용하지 않습니다.
- 화장품·퍼스널케어·건강/웰니스 상품은 용기·뚜껑·라벨·로고·인쇄 문자·색·용량·판매 단위를 AI가 다시 그리지 않습니다. AI 장면과 문구 편집 뒤 원본 상품 래스터를 보호 레이어로 다시 합성해 상품 동일성을 보존합니다.

## 완성 이미지 선택 후처리

광고 생성 엔진과 QA가 끝난 뒤에만 결과 화면에서 선택적으로 업체 로고와 `Ai생성이미지를활용하였습니다.` 고지를 적용할 수 있습니다. 로고는 제공된 16개 업체 투명 PNG 중에서 선택하며 우측 상단에, AI 고지는 선택한 경우에만 우측 하단에 작고 흐리게 들어갑니다.

아카이브에서는 로고 16개를 이미지 목록으로 모두 확인할 수 있으며, 적용 대상은 전체 필터 결과가 아니라 `업체 전체`, `상품 전체`, `이미지 개별` 중에서 선택합니다. 100장을 넘는 업체 선택은 서버 제한에 맞춰 자동 분할 처리하고, 적용이 끝나면 대상 선택을 초기화합니다.

- 기본값은 로고 없음·AI 고지 없음입니다.
- 현재 완성된 이미지 전체에 같은 설정을 일괄 적용합니다.
- 원본 생성 파일과 QA 결과는 변경하지 않고 `.data/generated/{advertiserId}/{jobId}/delivery/`에 다운로드용 파생본을 저장합니다.
- 개별 다운로드와 6장 ZIP은 적용된 파생본을 사용합니다.
- `원본으로 되돌리기`는 파생본 연결만 해제해 즉시 원본 다운로드로 복원합니다.

## 생성 결과와 보안

AI 편집 중간본, 수정본, 프롬프트, ProductTruth 원문, 레퍼런스 문구 프로필, QA 상세는 웹 공개 폴더에 두지 않습니다. Codex 세션 ID는 작업·manifest에 저장하지 않습니다.

```text
.data/generated/{advertiserId}/{jobId}/
  manifest.json
  product-analysis.json
  reference-copy-plans.json
  diversity-matrix.json
  references/
  H01/ ... H06/
  qa/

.data/creative-generation/jobs/
  creative-job-*.json

.data/codex/golden-references/{advertiserId}/
  golden-*.jpg
```

사용자 제공 ZIP에서 등록한 입력 레퍼런스는 제작 전 미리보기를 위해 `public/creative-references/reference-copy/`에 있습니다. 외부 배포 전에 해당 이미지의 사용 권리와 공개 범위를 확인해야 합니다. AI 중간 결과와 상품 원본 로컬 경로는 공개 응답에서 제거됩니다.

최종 광고도 `.data/generated`에 저장되며 localhost 접근 검사를 거치는 이미지·다운로드 API로만 전달됩니다. `public/generated`의 이전 native 결과는 다음 명령으로 비공개 저장소로 이전할 수 있습니다.

```bash
node scripts/migrate-native-generated-assets.mjs
```

사이트 URL 후보 분석 캐시는 `.data/site-candidates/cache.json`에 TTL, 원본 URL, 분석 결과, 선택 결과와 함께 저장되어 서버 재시작 후에도 복구됩니다.

## 주요 기능

### 광고 후보 찾기

- 쇼핑몰 URL 기반 상품 발견과 공개정보 분석
- BigQuery·크리마 데이터 연결 시 상품 기회 탐지
- 콘텐츠 적합도와 추천 근거 표시
- 선택 상품 URL을 제작 화면에 자동 전달

### 상세페이지로 광고 만들기

- 상품 정보와 원본 이미지 추출
- 상품 카테고리별 ZIP 광고 레퍼런스 6장 무작위 선택·작업 고정
- 선택된 레퍼런스별 문구 구조 분석 후 ProductTruth 기반 교체 문구를 한 번에 준비
- 레퍼런스 원본 무손실 복사 → 상품만 교체 → 문구만 교체 → 비생성 QA와 치명 오류 1회 보정
- 현재 제작 장수와 완료 `x/6`, 1~6 상태칸, 완성 결과 순차 표시
- 6장 완료 후 전체 ZIP 다운로드, 필요할 때만 개별 수정·승인·제외 도구 펼치기

### 자동 제작

- 초기 예시 광고주는 일시정지 상태이며, 사용자가 설정을 확인하고 명시적으로 활성화한 광고주만 Asia/Seoul 예약 실행
- 광고주별 상품 4개, 상품별 광고 6장, 몰당 24장·기본 일 72장
- 상품이 자동으로 선정된 뒤에는 수동 제작과 같은 `ProductTruth → 호환 ZIP 레퍼런스 6장 고정 → 레퍼런스별 문구 적응 → 원본 무손실 복사 → 상품 교체 → 문구 교체 → QA → ZIP` 흐름을 사용
- 자동제작 화면에서 오늘·어제·최근 7일·직접 기간별 실행을 조회하고 완성 이미지를 즉시 확인
- 이미지 개별 다운로드, 상품별 6장 ZIP, 광고주 실행 전체 ZIP과 아카이브 연결
- 관리자 설정, 광고주 최대 2개 동시 실행, 중복 방지, 중단 작업 복구
- SHA-256 기반 상품 작업 ID로 React key와 작업 기록의 고유성 보장

### 레거시 후킹 테스트와 성과 학습

- 과거 작업의 서로 다른 메시지 가설을 소재코드로 연결
- 캠페인 목표별 성과 연결
- 승인·제외·자연어 피드백은 표현 방향 학습에만 사용하며 판매 성과로 간주하지 않음
- `골든 레퍼런스로 등록`한 결과는 별도 학습 기록으로 비공개 저장
- 신규 기본 6장 선택과 문구 생성에는 후킹 성과 학습을 선행 입력으로 사용하지 않음
- 신규 reference-adapted 결과는 `소재 01~06`과 소재코드로 비교하며, 레퍼런스 구성·상품 표현·문구·레이아웃·Meta 노출 배분이 함께 반영된 완성 소재 성과로 해석
- 과거 HookPlan/H01~H06 기록은 읽기 전용 호환 대상으로 유지하되 신규 후킹 실험 생성 경로에는 사용하지 않음

### 영상 제작 협업

- 이미지 광고 생성과 분리된 프로젝트별 영상 대본·제작·검수 흐름
- 소재코드 날짜는 서버 위치와 무관하게 Asia/Seoul 기준
- 영상 자체를 AI로 생성하거나 편집하는 모듈은 아님

## 레거시 도구

배경 라이브러리, 템플릿 렌더러, 누끼, Canvas/SVG/Sharp 합성, 직접 문구 편집 코드는 기존 기록과 관리 기능의 호환성을 위해 격리되어 있습니다. `/create-product` 기본 제작 화면에는 노출되지 않으며 AI-native 작업 생성 경로에서 호출하지 않습니다.

- Next.js App Router
- TypeScript / React
- `@openai/codex-sdk`
- 선택형 OpenAI API
- sharp
- JSON 파일 저장(MVP)
- BigQuery / Crema 선택 연동

## 로컬 실행

요구 사항:

- Node.js 20 이상
- Codex CLI 설치 및 `codex login`

```bash
npm install
cp .env.example .env.local
npm run dev
```

브라우저에서 [http://localhost:3000](http://localhost:3000)을 엽니다. native 광고 생성 API는 기본적으로 localhost에서만 허용됩니다.

주요 환경변수:

```env
ADATLAS_CODEX_MODEL=gpt-5.6-sol
ADATLAS_CODEX_PLANNING_TIMEOUT_MS=180000
ADATLAS_CODEX_IMAGE_TIMEOUT_MS=720000
ADATLAS_CODEX_VALIDATION_TIMEOUT_MS=150000
ADATLAS_CREATIVE_COUNT=6
ADATLAS_CREATIVE_CONCURRENCY=3
ADATLAS_CODEX_MAX_PARALLEL_RUNS=3
ADATLAS_AUTO_REVISION_LIMIT=1
ADATLAS_PAID_API_EXPLICIT_ENABLED=false
```

유료 API 사용 시에만 `OPENAI_API_KEY`를 서버 환경에 두고 `ADATLAS_PAID_API_EXPLICIT_ENABLED=true`를 설정합니다. 어떠한 키도 `NEXT_PUBLIC_*`로 노출하지 않습니다.

## 현재 한계

- AI가 만든 패키지 라벨과 한국어가 매번 완벽하다고 보장할 수 없어 독립 QA와 사용자 승인이 필요합니다.
- 레퍼런스 디자인 충실도와 상품 동일성은 이미지 편집 모델의 한계에 영향을 받으므로 최종 집행 전 사람 검수가 필요합니다.
- 로컬 Codex 로그인, 이미지 생성 기능, 충분한 실행 시간이 필요합니다.
- 사이트 URL 분석은 공개 페이지에서 확인되는 사실만 사용하며 판매량·전환율·ROAS를 예측하지 않습니다.
- JSON 파일 저장은 단일 서버 MVP에 적합하며 다중 인스턴스 운영에는 공유 데이터베이스와 작업 큐가 필요합니다.
- 사이트 내부 알림만 구현되어 있으며 Slack·메일 알림은 아직 제공하지 않습니다.
